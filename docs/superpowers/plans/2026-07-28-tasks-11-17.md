# Lucky3D Tasks 11—17 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the approved V1 Android user flows, app-local reminders, release validation, and installable APK for Tasks 11 through 17.

**Architecture:** Keep the single `app` module and existing package boundaries. Feature ViewModels consume repositories and pure domain services, expose one immutable `UiState`, and never read DAOs or network DTOs. Room remains the runtime source of truth; Preferences DataStore stores only user settings and reminder de-duplication keys.

**Tech Stack:** Kotlin 2.4.10, Jetpack Compose Material 3, Navigation 3 1.1.4, Room 3.0.0, Hilt 2.60.1, Coroutines/Flow, Preferences DataStore, JUnit, Compose UI Test.

## Global Constraints

- Android phone portrait; `minSdk 26`, `compileSdk 37`, `targetSdk 37`, JDK 17.
- Navigation order is 首页、走势、选号、方案、彩报; no sixth primary destination.
- Only 福彩3D with 单选、组选3、组选6; always preserve three-digit strings.
- No cloud backend, account, purchase, payment, AI recommendation, sharing, export, backup, or online 彩报.
- UI follows `design-spec.md`, uses at least `48dp` targets, supports dark mode, large fonts, TalkBack, and narrow screens.
- All draw UI reads Room-backed repository flows; failed network payloads never directly update UI.
- Domain/filter/replay changes use failing tests first; each implementation batch ends with focused tests and `git diff --check`.
