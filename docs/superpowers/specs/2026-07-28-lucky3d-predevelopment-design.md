## 1. 已确认决策

1. 只开发 Android 客户端，不建设自有云后端，也不把开发者个人电脑作为服务端。
2. 安装包内置官方可核验的福彩3D历史开奖基线。
3. 应用打开、回到前台或用户手动刷新时，客户端直连福利彩票官方公开查询接口做增量更新。
4. 本地 Room 数据库是运行时唯一事实来源；页面不直接消费网络响应。
5. 首版没有账号、登录、跨设备同步、在线购彩、支付、社区或AI荐号。
6. V1 彩报首版只展示随安装包内置的合法来源静态占位图；该历史决策已由 V1.1/V1.2 的受控 A11 在线阅读、私有缓存和按期切换替代，图谜与第三方分析文章仍不在范围内。
7. 一级导航固定为首页、走势、选号、方案、彩报五项。
8. 首版投注玩法固定为单选、组选3和组选6。

## 2. 技术边界与默认值

### 2.1 平台

- 开发语言：Kotlin。
- 界面：Jetpack Compose + Material 3。
- 最低系统：Android 8.0，`minSdk 26`。
- 编译与目标系统：使用本机已有 Android 37 SDK，`compileSdk 37`、`targetSdk 37`。
- Java工具链：JDK 17。
- 默认应用名：Lucky3D。
- 默认包名：`com.lucky3d.app`。第一次公开发布前仍可修改；发布后不再更换，以免形成不同应用身份。
- 继续支持简体中文和手机竖屏；走势图使用页面纵向连续滚动、右侧完整数据区横向滚动和动态全列缩放。

### 2.2 主要库

- 导航：Navigation 3。
- 本地数据库：Room。
- 网络：OkHttp。
- JSON：kotlinx.serialization。
- 并发与状态：Kotlin Coroutines、Flow、StateFlow。
- 依赖注入：Hilt。
- 小型设置：Preferences DataStore。
- 首版不引入WorkManager；同步只发生在应用进入前台或用户手动刷新时。

具体依赖版本在创建工程时从官方稳定版本确定并锁定，不使用动态版本。

## 3. 工程结构

首版使用一个`app`模块，通过包边界分层。这样可以减少初期Gradle和跨模块配置成本，同时保留未来拆分能力。

```text
com.lucky3d.app
├─ app
│  ├─ Lucky3DApplication
│  ├─ MainActivity
│  └─ navigation
├─ core
│  ├─ model
│  ├─ result
│  ├─ time
│  └─ ui
├─ data
│  ├─ local
│  │  ├─ entity
│  │  ├─ dao
│  │  └─ migration
│  ├─ remote
│  │  ├─ dto
│  │  └─ OfficialFc3dDataSource
│  ├─ mapper
│  └─ repository
├─ domain
│  ├─ attributes
│  ├─ omission
│  ├─ filter
│  ├─ backtest
│  └─ replay
└─ feature
   ├─ home
   ├─ trend
   ├─ pick
   └─ scheme
```

约束：

- `feature`不能直接访问DAO或网络DTO，只依赖Repository和领域模型。
- `domain`中的计算规则是无Android依赖的纯Kotlin代码。
- 网络DTO、Room Entity和界面模型分别定义，不共用可变数据对象。
- 跨层错误使用明确类型表示，不通过异常文本驱动界面。

## 4. 状态与数据流

采用单向数据流：

```text
用户操作
  → ViewModel事件
  → Use case / Repository
  → Room事务或同步任务
  → Room Flow
  → ViewModel UiState
  → Compose界面
```

每个页面只有一个公开的不可变`UiState`。旋转屏幕或进程内重建时，由ViewModel和持久层恢复状态。

网络同步不把响应直接发给界面。只有通过校验并写入Room后，Room Flow才触发界面更新，从而避免“首页是新数据、走势图还是旧数据”的不一致。

## 5. 数据模型

### 5.1 开奖记录 `draw`

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| `issue` | String，主键 | 七位期号 |
| `drawDate` | LocalDate的ISO字符串 | 开奖日期 |
| `hundreds` | Int | 百位，0—9 |
| `tens` | Int | 十位，0—9 |
| `ones` | Int | 个位，0—9 |
| `source` | String | 固定为官方数据源标识 |
| `officialDetailUrl` | String? | 官方详情地址 |
| `contentFingerprint` | String | 期号、日期和号码生成的摘要 |
| `fetchedAt` | Instant字符串 | 最近获取时间 |
| `correctedAt` | Instant字符串? | 官方数据发生变化的时间 |

常用单期属性不重复持久化，避免规则升级后数据库中存在旧计算结果。和值、跨度、形态等由纯函数即时计算；性能测试证明必要时才增加带规则版本的缓存表。

### 5.2 同步元数据 `sync_metadata`

单行记录：

- 最后尝试时间。
- 最后成功时间。
- 本地最新期号。
- 最近失败类型与诊断码。
- 最近修正的期号集合。
- 当前内置数据版本和SHA-256。

### 5.3 方案 `scheme`

- 本地UUID。
- 对应期号。
- 玩法。
- 观察窗口。
- 筛选条件JSON及`conditionSchemaVersion`。
- 规则版本`ruleVersion`。
- 最终候选号码。
- 注数、倍数和金额。
- 标题、备注、创建和修改时间。
- 复盘状态。

已开奖方案不可覆盖原记录；编辑操作生成副本。

### 5.4 筛选模板 `filter_template`

- 本地UUID和名称。
- 玩法、观察窗口和筛选条件JSON。
- `conditionSchemaVersion`和`ruleVersion`。
- 创建和修改时间。

模板不保存某一期已经生成的候选集合。回测时必须按目标期之前的数据重新计算。

### 5.5 复盘记录 `replay`

- 方案UUID，唯一外键。
- 实际开奖号。
- 是否覆盖及命中候选。
- 复盘时使用的数据指纹和规则版本。
- 复盘时间。

官方数据修正导致指纹变化时，重新生成该期复盘。

### 5.6 用户设置

使用DataStore保存：

- 默认观察周期。
- 各类应用内提醒开关。
- 走势图显示偏好。
- 上次选择的首页/走势筛选项。

涉及业务完整性和关联关系的数据仍放在Room，不放入DataStore。

## 6. 内置数据与同步

详细协议、校验和失败规则见`docs/data-source-and-sync.md`。

### 6.1 安装包基线

- 源文件：`data/fc3d-seed.json`。
- 当前范围：2017001—2026198，共3334期；按产品决定去掉更早年份，2017年以前的数据不进入首版基线，也不在客户端按需补齐。
- 发布构建前将JSON转换为预置Room数据库。
- 首次安装通过Room `createFromAsset()`复制预置数据库。
- 已安装用户升级时只执行数据库迁移，不用新安装包中的基线覆盖用户数据库。

参考：[Prepopulate your Room database](https://developer.android.com/training/data-storage/room/prepopulate)、[Migrate your Room database](https://developer.android.com/training/data-storage/room/migrating-db-versions)

### 6.2 前台同步时序

```text
应用进入前台
  ├─ 立即订阅Room并显示本地最新一期
  ├─ 距上次成功同步不足5分钟 → 结束自动同步
  └─ 需要同步
       → 请求官方最近100期
       → 校验整批数据
       → 对比最近30期修正窗口
       → 必要时按期号分页补齐大缺口
       → 单事务插入新增/更新修正/写同步状态
       → 触发相关方案复盘
       → Room Flow刷新全部受影响页面
```

手动刷新绕过5分钟限制，但共享同一个互斥锁；已有同步执行时不再创建第二个请求。

### 6.3 网络契约

网络层只认稳定的领域结果：

- `NoChange`
- `Updated(newIssues, correctedIssues)`
- `Offline`
- `HttpFailure`
- `InvalidPayload`
- `SourceUnavailable`

官方接口地址和字段映射只存在于`OfficialFc3dDataSource`。接口结构变化时，应用保留本地数据并展示“数据源异常”，不写入部分解析结果。

## 7. 领域计算

所有公式以`docs/calculation-rules.md`规则版本1为准。

实现分为五组纯函数：

1. 单期属性：和值、和尾、跨度、奇偶、大小、质合、012路、形态、两码关系。
2. 跨期属性：重号、邻号。
3. 窗口统计：遗漏、次数、冷热。
4. 号码池：000—999、条件谓词、交集、冲突解释和玩法转换。
5. 方案处理：注数金额、模板历史回测、开奖复盘。

首轮实现必须先用`testdata/fc3d-golden-cases.json`形成单元测试，再写生产计算代码。

## 8. 关键页面设计

### 8.1 首页

```text
┌────────────────────────────┐
│ Lucky3D             [刷新] │
│ 已更新 07-28 09:15         │
├────────────────────────────┤
│ 最新 2026198期  2026-07-27 │
│       [ 6 ] [ 8 ] [ 5 ]    │
│ 和值19  跨度3  组六        │
├────────────────────────────┤
│ [查看走势]       [开始选号] │
├────────────────────────────┤
│ 待复盘方案 2               │
│ 最近方案摘要        [全部] │
└────────────────────────────┘
  首页      走势      选号      方案
```

状态规则：

- 页面先展示本地内容，标题区显示同步中进度。
- 断网显示“使用本地数据 · 上次更新……”和重试入口，不用全屏错误遮住历史数据。
- 有官方修正时展示一次可关闭说明，并链接到受影响期号。

### 8.2 走势

```text
┌────────────────────────────┐
│ Lucky3D      走势    本地数据│
├────────────────────────────┤
├────────┬───────────────────┤
│[30期▼] │ 百位0—9 十位0—9… │
│期号 开奖│ ● · · · · · · · │
│ 6198 685│ · · ● · · · · · │
│   ...   │ 横向滚动三组号码 │
│待开奖×2 │                   │
│统计×4   │ 次数/当前/平均/最大│
└────────┴───────────────────┘
```

交互：

- 周期支持10期、30期、60期和100期，默认30期；右侧完整列顺序和全列缩放以 V1.2 规格为准。
- 期号固定在左侧；试机号、开奖号、百位、十位、个位及属性列共用右侧横向滚动，双指缩放按 V1.2 规格等比作用于整张表。
- 点击落点显示期号、开奖号、位置、数字和本期遗漏。
- 不提供位置筛选、日历、“回到最新”或缩放按钮；走势图使用双指整体缩放，固定栏或右侧的单指纵向手势都更新统一 viewport。
- 颜色不是唯一编码，同时使用数字、形状或文字，保证色觉差异用户可辨认。
- 已开奖行后连续显示两期待开奖空白行和四行遗漏统计。

### 8.3 选号

```text
┌────────────────────────────┐
│ 选号    [单选▼]  2026199期 │
├────────────────────────────┤
│ 已启用条件 3               │
│ 胆码: 1,2          [编辑]  │
│ 和值: 6—15         [编辑]  │
│ 形态: 排除豹子     [编辑]  │
│ [+ 添加条件]               │
├────────────────────────────┤
│ 剩余 54注   单倍 ¥108      │
│ 012 021 102 ...      [查看]│
├────────────────────────────┤
│ [保存模板]       [保存方案]│
└────────────────────────────┘
```

交互：

- 每个条件显示单独排除数量，可停用、编辑和删除。
- 条件变化后立即显示剩余注数和金额。
- 结果为空时指出已知冲突，如胆码与杀码重叠，并提供撤销最后操作。
- 大量候选号码使用惰性列表，不一次创建全部Compose节点。
- 应用不提供“推荐”“预测”“必中”等按钮和措辞。

### 8.4 方案

```text
┌────────────────────────────┐
│ 方案          [方案|模板]  │
├────────────────────────────┤
│ 2026199期 和值跨度组合     │
│ 54注 ¥108       等待开奖   │
│                            │
│ 2026198期 组六观察         │
│ 18注 ¥36        未包含 685 │
├────────────────────────────┤
│ [回测模板] 选择范围/查看结果│
└────────────────────────────┘
```

方案详情显示原始条件、候选集合、备注、金额和复盘，不把历史覆盖率解释为未来中奖概率。

## 9. 错误与空状态

| 场景 | 用户看到的内容 | 系统行为 |
| --- | --- | --- |
| 无网络 | 本地数据、上次更新时间、重试按钮 | 不清库、不重复弹窗 |
| 官方返回空列表 | “数据源暂不可用” | 不推断未开奖、不写库 |
| 返回字段变化 | “数据源格式异常” | 整批拒绝并记录诊断码 |
| 内置数据库不可打开 | 恢复指引 | 禁止使用空白或部分数据计算 |
| 筛选无结果 | 冲突提示、撤销入口 | 保留用户全部条件 |
| 回测历史不足 | 标记样本不足 | 不计入覆盖率分母 |
| 还没有方案 | 示例说明和开始选号入口 | 不显示虚构数据 |

错误日志不得包含用户备注、完整方案内容或其他非诊断必需信息。

## 10. 测试策略

### 10.1 纯逻辑单元测试

以`testdata/fc3d-golden-cases.json`覆盖：

- 000、007、112、123、685、999的全部基础属性。
- 组选3与组选6排列和去重。
- 1000号码池及典型筛选后的精确数量。
- 重号、邻号、遗漏和冷热边界。
- 金额、倍数边界和规则版本。

### 10.2 数据层测试

- 官方正常响应、空响应、字段缺失、重复期号、非法号码和分页缺页。
- 新增期次、无变化、官方修正、长时间未更新补齐。
- 整批校验失败时数据库保持原状。
- 预置数据库首次复制。
- 每个Room版本的自动迁移或手写迁移测试。

### 10.3 功能与界面测试

- 无网首启可查看内置数据。
- 本地先显示、网络后更新且页面间数据一致。
- 30期/100期趋势与统计同步切换。
- 条件增删、冲突说明、候选列表、注数与金额联动。
- 方案保存、进程重建、复制、复盘和数据修正重算。
- 字体放大、窄屏、深浅色模式和TalkBack关键标签。

### 10.4 发布门槛

1. 基线JSON记录数、唯一期号、排序、号码范围和SHA-256校验通过。
2. 领域黄金测试全部通过。
3. 数据同步与Room迁移测试全部通过。
4. Debug与Release构建通过，无动态依赖。
5. 至少一台模拟器完成无网首启、联网同步、保存和复盘主流程。
6. 随机抽查最近100期，与官方来源逐期一致。

## 11. 隐私、安全与合规

- 应用无需注册、手机号、通讯录、定位、相机或存储权限。
- 只申请网络权限；如后续使用系统通知，再在需要时请求通知权限。
- 所有方案和备注只保存在用户设备内。
- 官方详情链接只允许HTTPS且限制在福利彩票官网域名，防止接口内容注入任意跳转。
- 产品全程说明“仅供数据分析，不销售彩票，不承诺预测结果”。
- 不接入支付、代购、专家荐号或诱导连续投注功能。

## 12. 开始编码的准入条件

开始创建Android工程前，需要产品负责人确认本设计稿。确认后再生成逐任务实施计划，顺序应为：

1. 工程与质量门禁。
2. 黄金测试和纯计算核心。
3. Room预置数据库与Repository。
4. 官方数据同步。
5. 首页和历史查询。
6. 走势与统计。
7. 选号、模板和方案。
8. 回测与复盘。
9. 全流程验收和Release构建。

当前不阻塞首轮开发的默认值包括应用名Lucky3D、包名`com.lucky3d.app`和`minSdk 26`；若要调整，应在第一次公开发布前完成。
