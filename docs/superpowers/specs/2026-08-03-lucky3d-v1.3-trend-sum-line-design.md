# Lucky3D V1.3 和值 0—27 连线走势图设计

> V1.4 仅替代本文件中“固定期号栏不变”的布局约束；和值 `0—27`、遗漏统计和统一 viewport 计算口径继续有效。当前期号列行为以 [V1.4 展示时序与页面导航规格](2026-08-09-lucky3d-v1.4-display-and-navigation.md) 为准。

>

>
> 平台：Android 手机，Jetpack Compose + Material 3

## 1. 目标

把综合走势图中现有的单格“和值”文字列替换为完整的 `0—27` 遗漏连线图，让用户在同一张表中观察和值落点、跨期变化和遗漏统计。

本阶段只改变走势图的和值呈现，不改变开奖同步、试机号同步、其他属性公式、选号、方案和彩报行为。

## 2. 已确认决策

1. 产品阶段升级为 V1.3，最终 Android 版本为 `1.3.0 / 3`。
2. 原单格“和值”列不再保留，改为一个横跨 28 个子列的“和值”分组。
3. 子列固定为 `0—27`，顺序从左到右递增。
4. 每期实际和值使用朱砂红实心圆、白色数值，并与相邻期次的和值落点使用实线连接。
5. 同一期其余 27 个和值格显示该和值截至本期的遗漏值。
6. 表尾的出现次数、当前遗漏、平均遗漏、最大遗漏四行均对 `0—27` 分别计算并显示。
7. 和尾、跨度、奇偶比、大小比、012路个数比继续使用普通文字列。
8. 新和值分组进入现有统一 viewport，双指中心缩放、横纵拖动、固定期号栏和边界夹紧逻辑不变。
9. 不新增缩放按钮、图例、筛选器、详情条或其他入口。
10. 本阶段先在本地开发和验收，未经用户后续明确指示不得上传 GitHub 或更新 Release。

## 3. 表格结构

V1.3 的右侧列顺序为：

```text
试机号 → 开奖号
→ 百位 0—9 → 十位 0—9 → 个位 0—9
→ 和值 0—27
→ 和尾 → 跨度 → 奇偶比 → 大小比 → 012路个数比
```

表头使用两层结构：

```text
第一层：试机号 | 开奖号 | 百位 | 十位 | 个位 | 和值 | 和尾 | ...
第二层：                  0—9   0—9   0—9   0—27
```

- “和值”第一层表头横跨 28 个等宽单元格。
- 和值子列沿用数字走势单元格宽度、行高、网格线和等宽数字字体。
- 和值分组与相邻分组使用较强分隔线，组内使用普通细网格线。
- 两期待开奖行的 28 个和值格保持空白，不伪造落点或遗漏。

## 4. 数据与计算口径

### 4.1 和值序列

每期开奖的和值继续使用唯一公式：

```text
sum = hundreds + tens + ones
```

合法范围为 `0—27`。计算必须复用 `DrawAttributes.sum`，不得在 UI 层重新定义另一套和值公式。

### 4.2 每期遗漏

对每个目标和值 `s ∈ 0—27`：

- 当期和值等于 `s` 时，该格为命中点，遗漏为 `0`。
- 当期和值不等于 `s` 时，遗漏从上一次命中后的下一期开始逐期加一。
- 当前可见窗口的首行遗漏必须继承窗口以前的完整历史，不能在切换 10/30/60/100 期时从零重算。

### 4.3 四行统计

对 `0—27` 的每个和值分别计算：

- 出现次数：只统计当前选择的 10/30/60/100 期窗口。
- 当前遗漏：使用从 `2017001` 起的全部本地可用开奖记录。
- 平均遗漏：使用完整历史中已经结束的遗漏段，保留两位小数；没有已结束段时显示 `--`。
- 最大遗漏：使用完整历史中已经结束的遗漏段；没有已结束段时显示 `--`。

统计规则必须与百位、十位、个位的现有遗漏口径一致，不读取未来期次，不受缩放、横滑或选中状态影响。

## 5. 领域模型与分层

### 5.1 遗漏算法

现有 `OmissionCalculator` 只允许 `0—9`。V1.3 将其核心计算扩展为显式接收合法值域：

```kotlin
calculate(values, target, allowedRange)
calculateVisibleWindow(values, target, visibleWindowSize, allowedRange)
```

- 现有数字位置调用继续传入 `0..9`，行为和结果必须完全不变。
- 和值调用传入 `0..27`。
- 输入值或目标值超出显式范围时立即失败，禁止静默截断或跳过。

不新建第二套和值遗漏算法，避免两套算法随时间产生口径偏差。

### 5.2 走势图状态

`buildTrendState` 在纯 Kotlin 层生成：

- 每期 `sum` 整数值。
- 每期 28 个和值遗漏值，顺序与 `0—27` 一致。
- 28 个和值的四项统计。

Canvas 只消费已经计算好的不可变状态并负责坐标、文字和图形绘制，不在绘制阶段遍历完整历史重新计算统计。

### 5.3 Room 与网络

本阶段不修改 Room Schema、DAO、开奖网络 DTO、试机号来源或同步元数据。和值和遗漏始终由 Room 中的正式开奖记录派生。

## 6. 绘制与交互

### 6.1 坐标

- 原三位置区共 30 个数字单元格。
- 新和值区紧随其后，共 28 个数字单元格。
- 普通属性区由原来的 6 列减少为 5 列。
- 逻辑总宽度按“2个前缀列 + 30个位置列 + 28个和值列 + 5个普通属性列”重新计算。
- `fitScale` 必须使用新逻辑总宽度动态计算，禁止写死某台设备的比例。

### 6.2 落点与连线

- 落点中心位于目标和值子列中心和当前期行中心。
- 圆点半径、线宽、文字字号随统一缩放比例变化。
- 连线先绘制，圆点后绘制，保证命中数字清晰。
- 颜色之外同时使用圆形、白色数字和实线表达命中，不只依赖朱砂红。
- 当前阶段不增加和值落点点击详情；现有百十个位点选行为保持不变。

### 6.3 缩放与滚动

- 新宽度只影响横向内容边界和最小全览比例。
- 双指缩放仍以双指质心为锚点，未触边时锚点下逻辑位置不漂移。
- 放大后单指横滑能够到达最右属性列。
- 右侧和值区域单指纵滑必须继续驱动统一纵向 viewport。
- 缩小再放大、先下滑再右滑均不得出现大面积空白。

## 7. 状态与文字替代

- 正常状态：显示真实开奖记录、和值遗漏、落点、连线和四行统计。
- 加载状态：沿用走势图现有加载状态，不绘制伪造值。
- 空状态：沿用现有无开奖记录说明。
- 数据不足：按实际记录计算；平均遗漏或最大遗漏没有样本时显示 `--`。
- 两期待开奖行：和值区域保持空白。
- Compose semantics 的表头摘要增加“和值0至27连线走势”；每期摘要继续直接读出实际和值。

## 8. 性能边界

- 最大可见窗口仍为 100 期。
- 新增状态规模为最多 `100 × 28` 个和值遗漏整数和 28 组统计，保持有界。
- 完整历史计算留在 ViewModel 构建阶段，Canvas 每帧只绘制可见状态。
- 不引入新依赖、后台任务或数据库表。

## 9. 测试设计

### 9.1 纯 Kotlin 单元测试

1. 扩展后的遗漏算法在 `0..9` 上与现有黄金结果完全一致。
2. `0..27` 接受边界和值 `0`、`27`，拒绝 `-1`、`28` 和越界历史值。
3. 真实号码 `000`、`009`、`999` 分别生成和值 `0`、`9`、`27`。
4. 每期和值遗漏列表固定为 28 项，命中项为 `0`。
5. 10/30/60/100 窗口只改变出现次数，不重置历史遗漏。
6. 平均遗漏和最大遗漏沿用已结束遗漏段口径。

### 9.2 坐标与 viewport 测试

1. 逻辑宽度包含 28 个和值单元格并移除原单格和值属性列。
2. 最小比例使用新总宽度计算。
3. 和值 `0`、`27` 的落点中心位于和值分组首尾子列中心。
4. 新宽度下缩放锚点、横纵偏移和边界夹紧回归测试继续通过。

### 9.3 Compose 设备测试

1. 表头语义包含“和值0至27连线走势”。
2. 真实 30 期数据能够横滑到和值区和最右属性列。
3. 和值区域单指纵滑、双指缩放可用，期数按钮不缩放。
4. 两期待开奖行和值为空，四行统计完整存在。
5. API 26 和 API 37 模拟器覆盖窄屏、浅色和深色基本显示。
