# Lucky3D 首页刷新与试机号失败状态修复规格

> 日期：2026-08-03
> 状态：用户已确认交互方向，待书面规格复核
> 版本：保持 `versionName 1.3.0`、`versionCode 3`

## 1. 问题与根因

首页紧凑状态栏当前存在两个不符合可见交互预期的绑定：

- 左侧“试机号 / ---”区域被实现为隐藏的试机号刷新入口；
- 中间可见的刷新入口只刷新官方开奖号，不刷新试机号。

因此用户点击可见刷新入口后，试机号不会发起手动刷新；首次进入时后台自动刷新尚未完成，也会表现为本次打开是 `---`、后续进入才看到号码。

## 2. 已确认交互

采用统一刷新方案：

1. 中间可见刷新入口一次同时触发官方开奖号刷新和试机号手动刷新；两项任务相互独立，一项失败不能阻止另一项执行。
2. 左侧试机号展示区改为纯展示，不响应点击，也不再承担隐藏刷新功能。
3. 刷新入口的无障碍语义明确为“刷新开奖号和试机号”。
4. 详细试机号状态区原有“重试试机号”入口仍只重试试机号。

## 3. 紧凑试机号状态

状态判断统一使用 `Asia/Shanghai`，发布时间分界保持每天 `18:30`：

| 条件 | 紧凑区显示 |
| --- | --- |
| 存在今天且晚于最新官方开奖期的有效试机号 | 三位号码，保留前导零 |
| 当日有效试机号不存在，当前时间早于 `18:30` | `---` |
| 当日有效试机号不存在，用户在 `18:30` 后点击统一刷新，试机号任务正在执行 | `---` |
| 当日有效试机号不存在，用户在 `18:30` 后点击统一刷新，试机号任务失败 | `失败` |
| 自动前台检查失败，但用户没有执行上述手动刷新 | `---` |

“失败”只描述本次用户发起的试机号刷新结果，不由官方开奖号刷新失败触发。成功取得当日有效试机号后，三位号码优先于失败状态显示；跨日后清除上一日的手动失败展示状态。

## 4. 状态与事件流

- 可见刷新入口调用现有官方开奖号刷新，并调用 `LiveRefreshTrigger.MANUAL` 的试机号刷新。
- `HomeViewModel` 保存仅供首页展示的“当日、发布时间后、最近一次手动试机号刷新失败”状态；Repository 继续负责网络校验、Room 写入和通用刷新元数据。
- 手动刷新成功时清除该失败状态；发布时间前的跳过或失败不显示“失败”；日期变化时清除该状态。
- Repository、试机号来源、18:30 自动调度、30 分钟冷却、每日自动尝试次数和 Room 契约均不改变。

## 5. 测试与验收

先写失败测试，再实现最小修复，至少覆盖：

1. 点击中间可见刷新入口同时调用开奖号与试机号两个回调；
2. 左侧试机号展示区不可点击，点击不会触发试机号刷新；
3. `18:30` 前没有当日号码时显示 `---`；
4. `18:30` 后手动试机号刷新失败且没有当日号码时显示“失败”；
5. 自动刷新失败但未发生用户手动刷新时仍显示 `---`；
6. 手动刷新成功后显示三位号码，并保留 `007` 等前导零；
7. 详细状态区的“重试试机号”仍只触发试机号刷新；
8. 官方开奖号刷新失败不错误地把试机号显示为“失败”。
