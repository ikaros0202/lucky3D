# Lucky3D 彩吧试机号来源与内置历史设计

> 状态：已确认，进入实施  
> 日期：2026-08-03  
> 适用版本：Lucky3D V1.2（`versionName 1.2.0` / `versionCode 2` 保持不变）

## 1. 目标

将试机号来源从彩经网切换到彩吧 55125，并让走势图在离线状态下也能读取完整上一年度及本年度截至打包日的历史试机号。修复首页跨日沿用昨天试机号的问题，并让应用在前台按彩吧公布时间自动检查今日数据。

## 2. 已确认来源

- 用户指定入口：`https://m.55125.cn/3dshijihao/list-80.htm`。
- 运行时历史与最新检查：`https://www.55125.cn/3dshijihao/list-80.htm`。该同站页面首行同时提供完整七位期号、日期和三位试机号，便于验证今日数据身份。
- 2025 年归档：`https://www.55125.cn/3d/3dsjhcx-2025.htm`。
- 2026 年归档：`https://www.55125.cn/3d/3dsjhcx-2026.htm`。
- 彩吧页面声明每天 `18:30` 后公布试机号；停止销售期间除外。

未发现需要调用的公开 JSON 接口。当前页面是服务端渲染 HTML，因此实现使用站点专用 HTML 适配器，不猜测或调用私有 `/api/` 路径。

## 3. 内置数据

APK 内置一份只包含试机号事实字段的 JSON：

```text
app/src/main/assets/trial/caiba-55125-trial-seed.json
```

范围固定为：

- 完整 2025 年；
- 2026 年从 `2026001` 至打包时彩吧已发布的最新期；
- 每条记录包含 `issue`、`sourceDate`、`number` 和 `sourcePageUrl`；
- 保留三位号码前导零。

构建数据脚本读取年度归档后必须验证：

1. 期号匹配 `20\d{5}`，且期号年份与归档年份一致；
2. 日期是合法 ISO 日期，且年份与归档年份一致；
3. 号码恰好三位，中文逗号或英文逗号只作为页面展示分隔符；
4. 相同期号的完全相同重复记录可以折叠；冲突重复必须使整次生成失败；
5. 2025 年从 `2025001` 连续到 `2025351`，2026 年从 `2026001` 连续到打包时最新期；
6. 生成结果按期号升序，附带来源页与生成时间，并通过独立校验命令复核。

## 4. 升级与 Room 导入

Room 继续作为运行时唯一事实来源。应用前台启动时先执行幂等种子导入，再执行今日联网检查：

1. 解析并整批验证内置 JSON；任一记录非法则不写库；
2. 查询 Room 已有试机号；
3. 缺失记录写入；旧来源的同一期记录由彩吧内置记录替换；已有彩吧联网记录不被较旧种子覆盖；
4. 全部待写记录在单个 Room 事务中批量 Upsert；
5. 导入不更新“今日联网刷新成功”元数据，避免把内置历史误判为当天在线更新成功；
6. 新安装和覆盖安装使用同一流程，不依赖重新创建预置数据库。

`TrialSource` 新增 `CAIBA_55125`。保留旧的 `CJCP_SIMULATED` 枚举只用于兼容升级前数据库行；内置导入会替换重叠期号，联网不再请求彩经网。

## 5. 运行时适配器与校验

彩吧 HTML 适配器只接受批准的 HTTPS 主机和固定路径，不跟随跨页重定向，响应大小受限。解析表格时要求唯一的期号、日期和试机号列，并输出：

```kotlin
data class TrialRemoteRecord(
    val issue: String,
    val sourceDate: LocalDate,
    val number: String,
)
```

最新检查读取列表首行，并额外要求：

- `sourceDate == Asia/Shanghai` 下的今天；
- `issue` 晚于本地最新官方开奖期；
- 期号、日期和号码均通过结构校验。

如果页面仍是昨天数据、返回空表、结构变化、发生冲突重复或网络失败，本次刷新失败并保留 Room 原数据。由于首页还执行当天身份过滤，昨天记录不会伪装成今日试机号。

走势图缺失历史时可以从同一 `list-80` 页面补齐最近最多 80 期。内置范围已经覆盖发布时的 2025 全年和 2026 年至打包日，日常成功刷新会逐期追加新数据。

## 6. 自动更新与跨日显示

统一使用 `Asia/Shanghai`：

- 自动检查起点由 `16:35` 改为 `18:30`；
- 应用启动、从后台回到前台或首页可见时执行资格检查；
- 首页在前台持续打开并跨过 `18:30` 时自动检查；
- 失败后冷却 30 分钟，每个自然日最多三次自动尝试；用户手动刷新不受次数限制；
- 应用完全关闭时不使用 WorkManager、AlarmManager、后台服务或常驻轮询；下次打开后补检查。

首页只显示“今天且晚于最新官方开奖期”的彩吧试机号。没有满足条件的记录时显示 `---`，包括：

- 次日零点后至今日试机号发布前；
- 页面仍返回昨天数据；
- 网络、解析或数据库失败；
- 本地只有历史种子或昨日缓存。

前台定时逻辑必须按北京时间日期重建，不能使用一个永不重置的布尔值跨日阻止新一天刷新。到达 18:30 后如首次仍未发布，应遵循 Repository 冷却时间继续调度剩余自动尝试。

## 7. 产品边界

- 试机号不写入 `draws`，不参与遗漏、冷热、筛选、回测、方案复盘或正式开奖结果同步。
- 页面只显示用户需要的“试机号”和号码，不增加抓取来源、缓存机制等开发信息。
- 不抓取预测、推荐、杀码、文章或其他彩种内容。
- 不新增服务器、账号、推送、支付、购彩或后台常驻能力。

## 8. 测试与验收

先写失败测试，至少覆盖：

1. 彩吧真实脱敏结构可解析完整期号、日期和三位号码，`007` 不丢前导零；
2. 非法表头、缺失日期、冲突重复、超限载荷、跨主机重定向和错误路径被拒绝；
3. 列表仍是昨天数据时不提交为今日刷新成功；
4. 18:29 不自动请求，18:30 可以请求；冷却、每日三次和手动刷新规则保持正确；
5. 次日只有昨天缓存时首页显示 `---`，今日合法记录发布后自动显示；
6. 前台跨过 18:30 会检查，失败后按冷却重试，跨日后调度状态重建；
7. 内置 JSON 覆盖 2025 全年及 2026 至打包日，记录连续、唯一、三位号码有效；
8. 内置导入对新安装和旧数据库都幂等，替换旧来源但不覆盖更新的彩吧记录；
9. 走势图按期读取内置历史，缺失仍显示 `—`；
10. 完整单元测试、lint、Debug/Release 构建、数据验证和相关设备测试通过。
