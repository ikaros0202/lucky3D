# Lucky3D 福彩3D计算规则

> 状态：开发前计算口径
> 日期：2026-07-28
> 规则版本：1

## 1. 基础表示

每期开奖号码表示为：

```text
(hundreds, tens, ones)
```

三个位置分别为百位、十位、个位，每个位置是0—9的整数。显示时始终保留三位，例如`007`不能显示为`7`。

所有规则函数必须是纯函数：相同输入和相同历史窗口永远得到相同输出。

## 2. 单期属性

设开奖号码为`(a, b, c)`。

### 2.1 和值

```text
sum = a + b + c
```

范围：0—27。

### 2.2 和尾

```text
sumTail = sum % 10
```

范围：0—9。

### 2.3 跨度

```text
span = max(a, b, c) - min(a, b, c)
```

范围：0—9。

### 2.4 奇偶

- 奇数：1、3、5、7、9
- 偶数：0、2、4、6、8

输出：

- 每个位置的奇偶属性。
- 奇数个数与偶数个数。
- 形态字符串，例如`奇偶奇`。

### 2.5 大小

单个数字：

- 小：0—4
- 大：5—9

输出：

- 每个位置的大小属性。
- 大数个数与小数个数。
- 形态字符串，例如`小小大`。

和值大小另行计算：

- 和值小：0—13
- 和值大：14—27

和值三区：

- 低区：0—8
- 中区：9—18
- 高区：19—27

单个数字大小、和值大小和和值三区是三个不同指标，UI不得共用一个没有说明的“大小”标签。

### 2.6 质合

采用福彩3D分析工具常用的五比五约定：

- 质：1、2、3、5、7
- 合：0、4、6、8、9

该约定不是数学上的质数定义。界面说明中必须明确“1按彩票分析惯例归入质数”。

输出：

- 每个位置的质合属性。
- 质数个数与合数个数。
- 形态字符串，例如`质质合`。

### 2.7 012路

```text
route(digit) = digit % 3
```

- 0路：0、3、6、9
- 1路：1、4、7
- 2路：2、5、8

输出：

- 每个位置的路数。
- 0路、1路、2路的数量。
- 定位形态，例如`120`表示百位1路、十位2路、个位0路。
- 数量形态，例如`111`表示三路各出现一个数字。

定位形态与数量形态必须使用不同字段，不能都称为“012形态”。

### 2.8 基本组选形态

- 豹子：三个数字全部相同。
- 组选3：恰好两个数字相同。
- 组选6：三个数字各不相同。

三种形态互斥且覆盖全部000—999号码。

### 2.9 连号

只分析当期不同数字之间的自然相邻关系，不首尾循环：

- 二连号：去重排序后，存在一组差值为1的数字。
- 三连号：三个数字互不相同，排序后相邻差值均为1。
- 0与9不视为相邻。

例如：

- `112`：含二连号，不含三连号。
- `321`：含三连号。
- `909`：不含连号。

### 2.10 跨期重号

“重号”专指本期与上一期共同出现的不同数字，不用于描述当期内部的对子。

```text
repeatDigits = distinct(currentDigits) ∩ distinct(previousDigits)
```

输出重复数字集合和数量。

### 2.11 邻号

“邻号”专指相对于上一期号码的相邻数字。

对上一期每个不同数字`d`生成：

```text
d - 1（大于等于0时）
d + 1（小于等于9时）
```

合并去重后，与本期不同数字集合取交集。输出邻号集合和数量。0与9之间不循环。

## 3. 两码关系

分别计算：

- 百十：`(a, b)`
- 十个：`(b, c)`
- 百个：`(a, c)`

两码和：

```text
pairSum(x, y) = x + y
```

范围：0—18。

两码差：

```text
pairDifference(x, y) = abs(x - y)
```

范围：0—9。两码差统一使用绝对值。

## 4. 遗漏

### 4.1 当前遗漏

对某个目标值按期号升序扫描：

- 本期出现目标值：本期遗漏为0。
- 本期未出现：上一期遗漏加1。

某期页面显示的遗漏，是截至该期开奖之后的值。

### 4.2 完成遗漏段

目标值两次出现之间未出现的期数称为一次完成遗漏：

```text
completedOmission = currentHitIndex - previousHitIndex - 1
```

数据集中的第一次命中没有完整起点，不参加平均遗漏和最大遗漏计算。

### 4.3 平均遗漏

```text
averageOmission = completedOmissions.average()
```

- 只使用完成遗漏段。
- 保留两位小数。
- 完成遗漏段为空时返回`null`，UI显示`--`。

### 4.4 最大遗漏

```text
maxOmission = completedOmissions.max()
```

当前仍在增长的遗漏不计入“历史最大遗漏”，单独显示为当前遗漏。

### 4.5 窗口规则

- 遗漏序列使用本地全部已确认历史作为预热，不能从用户当前可见窗口重新从0开始。
- 出现次数和冷热标签使用用户选择的窗口。
- 用户切换30期或100期时，窗口内次数会变化，但同一期落点显示的历史遗漏值不变。

## 5. 冷热

首版只对以下对象显示冷、温、热标签：

- 百位0—9
- 十位0—9
- 个位0—9
- 三个位置合并后的0—9

单位置窗口为`N`期：

```text
expected = N / 10
activityRatio = occurrences / expected
```

三个位置合并：

```text
expected = 3 * N / 10
```

分类：

- 冷：`activityRatio < 0.8`
- 温：`0.8 <= activityRatio < 1.2`
- 热：`activityRatio >= 1.2`

UI同时显示实际出现次数和计算窗口，不能只显示冷、温、热标签。

和值、跨度等理论概率不均匀的指标，首版只显示次数和遗漏，不使用上述冷热阈值。

## 6. 号码池与筛选

### 6.1 初始号码池

单选号码池固定为：

```text
000, 001, 002, ... , 999
```

共1000个有序号码。

所有条件默认采用逻辑与：候选号码必须同时满足全部启用条件。

### 6.2 全局胆码

用户选择的每个不同胆码，必须至少在候选号码中出现一次。

- 最多选择3个不同胆码。
- 不表达重复次数。
- 对“必须出现两个1”这类需求，使用形态或定位条件表达。

### 6.3 全局杀码

任意杀码都不能出现在候选号码的任何位置。

胆码与杀码包含相同数字时视为条件冲突。

### 6.4 定位条件

百位、十位、个位各自维护允许数字集合。候选号码的对应位置必须包含在允许集合中。

定位杀码转换为对应位置允许集合的补集，不单独建立第二套执行逻辑。

### 6.5 范围与属性条件

和值、和尾、跨度、奇偶、大小、质合、012路、组选形态、连号及两码关系都转换为对单个候选号码返回真或假的谓词。

每个条件必须提供：

- 稳定类型标识。
- 用户可读标题。
- 完整参数。
- 匹配函数。
- 被该条件单独排除的号码数量。

### 6.6 胆拖生成

胆码和拖码是两个互斥数字集合：

- 结果必须包含全部胆码。
- 其余数字只能来自拖码。
- 再按单选、组选3或组选6的形态限制生成。
- 生成结果必须去重。

## 7. 玩法与注数

首版只保留三个明确玩法：

- 单选
- 组选3
- 组选6

“组选”只作为组选3和组选6的界面分组标题，不作为第四种独立玩法。

### 7.1 单选

每个三位有序号码是一注。全部号码共1000注。

### 7.2 组选3

每个“两个相同数字 + 一个不同数字”的无序组合是一注。

- 全部组选3共90注。
- 转成单选时产生3个不同排列。

示例：

```text
112 → 112, 121, 211
```

### 7.3 组选6

每个三个不同数字的无序组合是一注，内部使用升序形式保存。

- 全部组选6共120注。
- 转成单选时产生6个不同排列。

示例：

```text
123 → 123, 132, 213, 231, 312, 321
```

### 7.4 金额

```text
amount = betCount * 2元 * multiplier
```

- 默认倍数为1。
- 允许倍数为1—99。
- 金额只用于方案记录，不触发支付或下单。

## 8. 方案、模板与回测

### 8.1 方案

方案属于某一期，保存：

- 玩法
- 筛选条件快照
- 最终候选号码
- 注数和金额
- 备注

方案开奖后只做当期核对。

### 8.2 筛选模板

为了支持真正的历史回测，首版纳入基础筛选模板：

- 模板保存条件结构，不保存某一期生成的候选号码。
- 静态条件直接复用。
- 冷热、遗漏等动态条件必须保存观察窗口。
- 模板可以复制到新一期方案。

这解决原PRD中“回测依赖模板，但模板被列为后续功能”的冲突。

### 8.3 历史回测

对目标历史期`T`：

1. 只加载`T`之前的已确认开奖记录。
2. 按模板保存的观察窗口重新计算动态指标。
3. 生成`T`期候选号码。
4. 再与`T`期开奖核对。

禁止使用`T`期或之后的数据生成`T`期候选号码。

若目标期之前的记录不足模板观察窗口，该期标记为“样本不足”，不计入覆盖率分母。

## 9. 规则版本

每个方案、模板和回测记录都保存`ruleVersion`。

修改任何计算口径时：

- 增加规则版本。
- 旧方案保留旧版本结果。
- 新建方案使用最新版本。
- 不静默改写历史复盘。
