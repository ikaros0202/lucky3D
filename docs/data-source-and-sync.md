# Lucky3D 数据源与同步方案

> 状态：Tasks 7—10 已实现并验证
> 日期：2026-07-28
> 适用范围：福彩3D开奖数据
> 架构约束：不使用云端服务

## 1. 结论

首版采用“应用内置历史数据 + 客户端直接增量同步”的方案：

1. 应用安装包内置一份已经校验的福彩3D历史开奖基线。
2. 第一次启动时，用内置数据创建本地 Room 数据库。
3. 每次进入应用前台时，直接访问中国福利彩票官网公开查询接口。
4. 把新增或被修正的开奖结果合并进本地数据库。
5. 页面始终从本地数据库读取数据，网络请求不直接驱动页面。
6. 没有网络时继续展示本地已有记录，并显示最后成功更新时间。

本方案不依赖用户电脑，也不需要服务器、域名、账号系统或云函数。

## 2. 已验证的数据源

### 2.1 主数据源

- 来源：中国福利彩票官网
- 网站：[https://www.cwl.gov.cn/](https://www.cwl.gov.cn/)
- 查询接口：
  `https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice`
- 福彩3D参数：`name=3d`
- 返回形式：JSON

2026-07-28实测结果：

- HTTP状态：200
- 接口业务状态：`state=0`
- 可以查询最近N期。
- 可以按起止期号查询。
- 可以按起止日期查询。
- 可以分页。
- 当前官方接口可查询到第2013002期至第2026198期，但2013年存在62个期号缺口。
- 从第2017001期至第2026198期连续无缺期；按产品范围只打包这一段。
- 返回字段包含期号、开奖日期、三位号码、详情链接和销售额等信息。

接口不是公开承诺稳定性的开发者API，没有发现版本号、SLA或兼容性承诺。因此必须封装在独立数据源适配器中，不能在页面或业务代码中直接拼接接口URL。

### 2.2 暂不接入的来源

- 第三方免费彩票API：稳定性、数据责任和授权情况不明确。
- 论坛、彩票论坛和分析站：只作为需求调研依据，不作为开奖结果来源。
- 彩报联网内容：来源和展示授权尚未确定，首版不接入。当前仅打包一张已记录许可与署名的静态占位图，不属于开奖数据源，也不会联网更新。

## 3. 内置数据基线

仓库中的规范化基线：

- 文件：`data/fc3d-seed.json`
- 生成脚本：`tools/fetch-fc3d-seed.ps1`
- 数据范围：第2017001期至第2026198期
- 记录数量：3334
- SHA-256：`7D90B6074551476D5FDEDC989F001B20A9C3336476438F819E3F770C1757F4EA`

每条规范化记录只保留：

```json
{
  "issue": "2026198",
  "drawDate": "2026-07-27",
  "digits": [6, 8, 5],
  "officialDetailUrl": "https://www.cwl.gov.cn/c/2026/07/27/662242.shtml"
}
```

当前官方接口的2013年记录存在62个期号缺口，2014年至今的返回结果在各自然年内连续。产品选择进一步缩小基线，只内置2017001期及以后的数据；2017年以前的数据不进入首版，也不在客户端按需补齐。生成脚本会检查各年份期号连续性，发现缺口即停止生成。

独立抽样结果见[福彩3D内置开奖独立抽样核验](fc3d-independent-sample-audit.md)：使用不同域名的逐期HTML详情页核对2017—2026每年2期，共20期，日期和号码全部一致。

## 4. 本地存储

### 4.1 单一事实来源

Room数据库是应用运行时的单一事实来源：

- UI只订阅Room查询结果。
- 网络同步只负责校验并写入Room。
- 指标、走势图、筛选和回测只读取Room中的已确认记录。
- 不允许页面同时混用网络响应和本地记录。

这符合Android官方建议的数据层结构：上层通过Repository访问数据，Repository负责协调本地与网络数据源。
参考：[Android Data layer](https://developer.android.com/topic/architecture/data-layer)

### 4.2 预置数据库

应用工程建立后，将规范化JSON转换为预置Room数据库并放入`assets/database/`。首次安装使用Room的`createFromAsset()`复制数据库，避免在首屏启动期间解析数千条JSON。
参考：[Prepopulate your Room database](https://developer.android.com/training/data-storage/room/prepopulate)

预置数据库只负责新安装：

- 已安装用户继续保留自己的本地数据库。
- 后续版本不能通过覆盖预置数据库破坏用户方案。
- 数据库升级必须提供显式迁移。
- 禁止对包含用户方案的数据库使用无条件破坏性迁移。

## 5. 启动同步流程

### 5.1 前台自动同步

应用进入前台时执行：

1. 立即读取Room并显示本地最新结果。
2. 检查最近一次成功同步时间。
3. 若距离上次成功同步不足5分钟，则不自动重复请求。
4. 否则请求官方最近100期。
5. 校验返回内容。
6. 对比最近30期，识别官方修正。
7. 插入新增记录，更新发生变化的记录。
8. 在同一事务中更新同步状态。
9. Room数据变化后，由Flow自动刷新页面。
10. 若开奖结果发生修正，重新计算受影响的方案复盘。

用户点击“刷新”时绕过5分钟限制，但仍需防止并发重复请求。

### 5.2 跨越100期的补齐

正常使用时，最近100期足以完成增量同步。若本地最新期号早于接口最近100期的最早记录：

1. 从最近100期响应中取得远端最新期号。
2. 使用本地最后期号的下一期作为`issueStart`。
3. 使用远端最新期号作为`issueEnd`。
4. 分页下载缺失区间。
5. 全部分页通过校验后再执行数据库事务。

不使用`9999999`等虚构期号作为正式同步上限，避免接口边界行为变化。

### 5.3 后台更新

没有云端推送时，应用无法保证在关闭状态下立即收到开奖结果。

首版采用：

- 应用打开或回到前台时可靠同步。
- 用户手动刷新时可靠同步。
- 不注册周期后台同步任务，不在应用关闭时主动联网。
- 不承诺应用关闭期间的开奖或复盘通知。

若后续内测确认用户确实需要后台更新，可使用WorkManager做“尽力而为”的联网同步；Android官方说明其周期任务的准确执行时间会受到系统调度和省电策略影响，因此仍不能承诺准点推送。
参考：[Task scheduling](https://developer.android.com/develop/background-work/background-tasks/persistent)、[Define work requests](https://developer.android.com/develop/background-work/background-tasks/persistent/getting-started/define-work)

## 6. 校验和合并规则

### 6.1 单条记录校验

- `state`必须为0。
- 期号必须匹配7位数字。
- 开奖日期必须能解析为`yyyy-MM-dd`。
- 开奖号码必须恰好包含三个0—9数字。
- 同一期在一次响应中不能重复。
- 详情链接如存在，必须解析为福彩官网HTTPS地址。

### 6.2 合并规则

- 期号是唯一键。
- 新期号：插入。
- 已存在且号码、日期均相同：忽略。
- 已存在但号码或日期不同：记录为官方修正并更新。
- 校验失败：整批响应不写入数据库。
- 分页缺页：整个补齐任务失败并保留原有数据。

### 6.3 同步状态

本地保存：

- 最后尝试同步时间。
- 最后成功同步时间。
- 最后成功同步后的最新期号。
- 最近一次失败类型。
- 最近一次数据修正涉及的期号。

UI状态：

- `已更新`
- `正在更新`
- `使用本地数据`
- `更新失败，可重试`
- `数据有修正`

## 7. 失败处理

| 场景 | 行为 |
| --- | --- |
| 无网络 | 展示本地数据和最后成功更新时间 |
| HTTP失败 | 不修改数据库，允许重试 |
| JSON结构变化 | 视为解析失败，不写入部分结果 |
| 单条数据不合法 | 整批拒绝，记录失败原因 |
| 官方接口返回空列表 | 保留本地数据，不推断“没有开奖” |
| 同一期数据变化 | 更新该期并重做相关复盘 |
| 本地比远端更新 | 不删除本地记录，标记异常等待下一次校验 |

## 8. 发布前风险

| 风险 | 等级 | 缓解方式 |
| --- | --- | --- |
| 官方接口没有公开SLA | 高 | 独立适配器、严格校验、保留内置数据、允许通过发版更换接口 |
| 官方接口结构变化 | 高 | DTO与领域模型隔离，解析失败不污染Room |
| 应用长期未更新导致缺口超过100期 | 中 | 自动使用期号范围分页补齐 |
| 应用关闭期间没有更新 | 中 | 首页展示最后同步时间，打开应用或手动刷新即同步，不承诺即时通知 |
| 2017年以前数据不在应用内 | 低 | 查询页明确标示数据起点为2017001期 |
