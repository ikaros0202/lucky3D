## 3. 正式发行门禁

按以下顺序关闭：

1. 确认第三方彩报完整图片展示授权；未确认时不得公开正式发行当前默认能力。
2. 补齐并确认选号、彩报最终独立设计，完成 API 26/API 37 深浅色设计 QA。
3. 生成并长期安全保管生产签名，记录证书摘要和恢复流程。
4. 在至少一台接近 API 26 与一台当前 Android 的物理设备完成安装、升级、无网和主流程验收。
5. 清理或明确接受剩余 lint 警告，运行完整发布门禁。
6. 由产品负责人明确把 Draft Release 发布为正式版本。

## 4. 发布验证

```powershell
.\gradlew.bat test lint assembleDebug assembleRelease -PwarningsAsErrors=true --console=plain
powershell -ExecutionPolicy Bypass -File tools\validate-predevelopment-data.ps1
.\gradlew.bat connectedDebugAndroidTest --console=plain
```

发布前还要核对：

- APK 包名、版本、权限、签名证书与 SHA-256；
- 仓库不包含 APK/AAB、密钥、`.env`、`local.properties`、个人绝对路径或下载的彩报图片；
- GitHub 下载后的 APK 与本地产物逐字节身份一致；
- 模拟器/真机和 Gradle/Kotlin 后台进程在任务结束时完成收尾。

## 5. 完成定义

- 行为变更有失败路径和边界测试。
- 数据结构变化有历史 schema 与迁移测试。
- Room 仍是运行时唯一事实来源，网络失败不污染本地数据。
- UI 使用真实内容验证加载、空、错误、无网、重试和成功状态。
- PRD、架构、数据、计算、UI、任务和发布文档与实现一致。
- 工作树不包含可再生构建产物或已被当前实现替代的中间素材。
